# Step 8 – Sources CLI, CSV Export Adapter, and Knowledge Connectors

## Overview

This step adds three major capabilities to RevenueLens so it can operate end to
end against synthetic data without requiring a live database:

1. **CSV Export Adapter** – a DuckDB-backed read-only adapter that reads CSV
   files exported by `legacy_sim`.
2. **Knowledge Connectors** – lightweight readers over Jira tickets, Azure
   DevOps items, and Confluence pages.
3. **Sources CLI** – a command-line entry point that runs discovery, mapping,
   and reconciliation on either a CSV directory or a PostgreSQL database.

## CSV Export Adapter (`app/adapters/csv_export.py`)

`CsvExportAdapter` mirrors the interface of `ReadOnlyAdapter` (PostgreSQL):

| Method         | Description |
|----------------|-------------|
| `list_tables()`        | Returns sorted list of base tables in the schema. |
| `columns(table)`       | Returns `(column_name, data_type)` pairs. |
| `row_count(table)`     | Returns the number of rows in a table. |
| `sample(table, n)`     | Returns up to `n` sample rows. |
| `fetch_all(table, cols)` | Returns all rows, optionally filtered to specific columns. |
| `query(sql)`           | Executes a `SELECT` or `WITH` query and returns rows as dicts. |
| `close()`              | Closes the underlying connection. |

Key behaviors:

- Each `*.csv` file in `dir_path` becomes a table named after its stem
  (lowercased) inside the target schema.
- `query()` only allows `SELECT` or `WITH` statements; other commands raise a
  `ValueError`.
- `columns()` maps DuckDB types to PostgreSQL-style names (e.g. `VARCHAR` →
  `character varying`, `BIGINT` → `integer`).
- Numeric float values are converted to `decimal.Decimal(str(round(v, 4)))`
  to mimic psycopg behavior.

## Adapter Factory (`app/adapters/__init__.py`)

`open_source(kind, target, schema="nimbus")` returns either a
`ReadOnlyAdapter` ("postgres") or `CsvExportAdapter` ("csv"). This allows the
rest of the pipeline to switch transparently between backends.

## Knowledge Connectors (`app/knowledge.py`)

### `KnowledgeItem`

A dataclass with fields: `source`, `key`, `title`, `body`, `created`,
`labels`, `url`.

### Connectors

| Connector        | Source        | Constructor                 |
|------------------|---------------|-----------------------------|
| `JiraConnector`  | `tickets.json` | `from_export(path)`       |
| `AdoConnector`   | `tickets.json` | `from_export(path)`       |
| `ConfluenceConnector` | `pages/*.md` | `from_export(dir)`     |

Each connector exposes:

- `items()` – returns a list of `KnowledgeItem` objects.
- `search(text, labels=None)` – case-insensitive keyword search across
  title, body, and labels.

### Helpers

- `load_all(export_dir)` – loads all Jira/ADO tickets and Confluence pages.
- `as_tickets(items)` – converts items into the ticket dict shape expected by
  `app.explain.match_tickets`.

### URL Formats

- Jira: `https://jira.example.invalid/browse/KEY`
- Azure DevOps: `https://dev.azure.example.invalid/nimbus/_workitems/edit/KEY`
- Confluence: `https://confluence.example.invalid/pages/KEY`

## Sources CLI (`app/sources_cli.py`)

Run with:

```bash
python -m app.sources_cli --csv DIR [--knowledge KNOWLEDGE_DIR]
python -m app.sources_cli --postgres URL [--knowledge KNOWLEDGE_DIR]
```

It prints a JSON summary containing:

- `tables` – discovered tables
- `checks` – per-check record counts and money impact
- `total_money` – cumulative monetary impact of findings
- `findings` – total number of findings
- `knowledge_items` – (optional) number of knowledge items loaded

## Testing (`tests/test_step8_sources.py`)

Tests cover:

- CSV adapter listing tables, row counts, and query rejection.
- Knowledge connector source filtering, search, and ticket shaping.
- `run_checks` scoring precision/recall at 1.0 against ground truth.
- Postgres parity test (skipped if `DATABASE_URL` is unreachable).

All tests use synthetic data generated by `legacy_sim`.
